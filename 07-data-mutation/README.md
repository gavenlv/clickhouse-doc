## 核心原理

### Mutation 的本质

ClickHouse 的 ALTER TABLE UPDATE/DELETE 不是原地修改，而是**创建新的 Part 版本**：

```
旧 Part (part_1_1_0_1) → Mutation → 新 Part (part_1_1_0_2) + 旧 Part 标记为非活跃
```

这意味着：
- Mutation 是**异步**的（提交后立即返回，后台执行）
- Mutation 会产生**写放大**（重写整个 Part，不是只改几行）
- 删除不是真正删除，只是标记为非活跃（直到合并或清理）
- 频繁 Mutation 会导致 Part 数量爆炸

### 变更手段全景

```
┌─ 数据变更手段 ──────────────────────────────────────┐
│                                                        │
│  ① 分区操作（最快，推荐）                                │
│     ├─ DROP PARTITION     ─ 删除整个分区                  │
│     ├─ MOVE PARTITION     ─ 跨表/跨磁盘移动分区           │
│     ├─ REPLACE PARTITION  ─ 用另一表分区替换              │
│     └─ EXCHANGE PARTITION ─ 交换分区（原子操作）          │
│                                                        │
│  ② TTL（自动，推荐）                                     │
│     ├─ 列级 TTL  ─ 自动过期列值                          │
│     ├─ 行级 TTL  ─ 自动过期整行                          │
│     └─ GROUP BY TTL ─ 降采样聚合后过期                   │
│                                                        │
│  ③ Mutation（最后手段）                                   │
│     ├─ ALTER TABLE DELETE  ─ 按条件删除                  │
│     └─ ALTER TABLE UPDATE  ─ 按条件更新                  │
│                                                        │
│  ④ 轻量操作（CH 23.8+，优先用）                          │
│     ├─ 轻量 DELETE ─ 异步删除，写一个删除标记             │
│     └─ 轻量 UPDATE ─ 异步更新，写一个更新标记             │
│                                                        │
│  ⑤ 批量写入（避免变更，推荐）                             │
│     ├─ 异步 INSERT ─ 队列写入，合并为大批                 │
│     └─ Buffer 表   ─ 内存缓冲，定期刷盘                   │
│                                                        │
└────────────────────────────────────────────────────────┘
```

## 变更方法对比

| 方法 | 速度 | 资源消耗 | 立即生效 | 适用场景 |
|------|------|---------|---------|---------|
| DROP PARTITION | ⭐⭐⭐⭐⭐ | 极低 | 是 | 整分区删除 |
| TTL | ⭐⭐⭐⭐ | 低 | 延迟 | 自动过期 |
| 轻量 DELETE/UPDATE | ⭐⭐⭐⭐ | 低 | 异步 | 少量数据 |
| Mutation DELETE/UPDATE | ⭐⭐ | 高 | 异步 | 复杂条件 |
| 异步 INSERT | ⭐⭐⭐⭐ | 低 | 异步 | 大量写入 |

## 常见误区

1. **Mutation 是同步的**：错的，Mutation 提交后立即返回，后台异步执行
2. **轻量操作不会产生 Part**：错的，轻量操作也会产生新的 Part，只是写一个标记
3. **TTL 立即生效**：错的，TTL 在合并时执行，有延迟
4. **频繁更新删除没问题**：错的，频繁 Mutation 导致 Part 爆炸，严重影响查询性能
5. **DELETE 真的删除了数据**：错的，只是标记为非活跃，直到合并才真正清理
