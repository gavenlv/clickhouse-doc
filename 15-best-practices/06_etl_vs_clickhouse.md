# ETL vs ClickHouse: 职责划分最佳实践

本文档详细说明哪些操作应该在 ETL 阶段完成，哪些应该在 ClickHouse 中完成。

## 核心原则

```
┌─────────────────────────────────────────────────────────────────┐
│                    ClickHouse 设计哲学                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ClickHouse = 写入优化型数据库                                     │
│                                                                 │
│  ✓ 擅长: 大批量写入、高性能分析查询                              │
│  ✗ 不擅长: 频繁更新/删除、事务处理                               │
│                                                                 │
│  最佳实践: 数据进入 ClickHouse 前完成所有转换                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 应该在 ETL 中完成的任务

### 1. 数据清洗和验证

```
┌─────────────────────────────────────────────────────────────────┐
│                    ETL: 数据清洗和验证                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ETL 阶段:                                                       │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                                                          │   │
│  │  1. 空值处理                                            │   │
│  │     - 删除空值行                                        │   │
│  │     - 填充默认值                                        │   │
│  │     - 标记为 NULL                                       │   │
│  │                                                          │   │
│  │  2. 格式标准化                                          │   │
│  │     - 日期格式统一 (YYYY-MM-DD)                        │   │
│  │     - 去除前后空格                                      │   │
│  │     - 大小写统一                                        │   │
│  │                                                          │   │
│  │  3. 数据类型转换                                         │   │
│  │     - 字符串转日期                                      │   │
│  │     - 字符串转数值                                      │   │
│  │     - 枚举值映射                                        │   │
│  │                                                          │   │
│  │  4. 数据验证                                            │   │
│  │     - 范围检查                                          │   │
│  │     - 格式验证                                          │   │
│  │     - 业务规则验证                                      │   │
│  │                                                          │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  为什么?                                                         │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ • ClickHouse 没有强大的数据验证能力                       │   │
│  │ • 在 ETL 阶段处理更高效                                 │   │
│  │ • 避免脏数据进入分析系统                                 │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

示例 (ETL 代码 - Python):
─────────────────────────────────────────────────────────────────
# 错误数据清洗 (ETL)
import pandas as pd

df = pd.read_csv('raw_data.csv')

# 1. 删除空值
df = df.dropna(subset=['user_id', 'event_time'])

# 2. 格式标准化
df['event_time'] = pd.to_datetime(df['event_time']).dt.strftime('%Y-%m-%d')
df['phone'] = df['phone'].str.strip()
df['status'] = df['status'].str.upper()

# 3. 数据验证
df = df[df['amount'] >= 0]  # 过滤负数
df = df[df['user_id'].astype(str).str.len() <= 10]  # 长度限制

# 4. 写入 ClickHouse
df.to_clickhouse('events', index=False)
─────────────────────────────────────────────────────────────────
```

### 2. 数据去重

```
┌─────────────────────────────────────────────────────────────────┐
│                    ETL: 数据去重                                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ETL 阶段:                                                       │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                                                          │   │
│  │  1. 精确去重                                            │   │
│  │     - 基于业务主键                                        │   │
│  │     - 保留最新/最完整记录                                │   │
│  │                                                          │   │
│  │  2. 近似去重                                            │   │
│  │     - 布隆过滤器                                          │   │
│  │     - 用于超大数据量                                      │   │
│  │                                                          │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  为什么?                                                         │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ • ReplacingMergeTree 去重是异步的                        │   │
│  │ • 实时去重影响写入性能                                   │   │
│  │ • ETL 阶段去重更可控                                    │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

示例 (ETL 代码):
─────────────────────────────────────────────────────────────────
# 精确去重 (ETL)
df = pd.read_csv('raw_data.csv')

# 基于业务主键去重,保留最新记录
df = df.sort_values('updated_at').drop_duplicates(
    subset=['order_id'], 
    keep='last'
)

# 或者使用数据库去重
df.to_sql('temp_table', con, if_exists='replace')
df_dedup = pd.read_sql('''
    SELECT * FROM temp_table 
    GROUP BY order_id 
    HAVING MAX(updated_at)
''', con)
─────────────────────────────────────────────────────────────────
```

### 3. 数据关联和 JOIN

```
┌─────────────────────────────────────────────────────────────────┐
│                    ETL: 数据关联                                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ETL 阶段:                                                       │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                                                          │   │
│  │  1. 维度表关联                                           │   │
│  │     - 用户表JOIN用户属性                                  │   │
│  │     - 商品表JOIN商品分类                                  │   │
│  │                                                          │   │
│  │  2. 大表 JOIN                                            │   │
│  │     - 事实表JOIN事实表                                    │   │
│  │                                                          │   │
│  │  3. 预计算 JOIN 结果                                      │   │
│  │     - 生成宽表                                            │   │
│  │     - 物化视图源数据                                     │   │
│  │                                                          │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  为什么?                                                         │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ • ClickHouse JOIN性能相对较弱                           │   │
│  │ • ETL 可以使用更高效的 JOIN 引擎                        │   │
│  │ • 预JOIN 数据减少实时计算                               │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

示例:
─────────────────────────────────────────────────────────────────
# ETL 预JOIN (生成宽表)
orders = pd.read_sql('SELECT * FROM orders', db_conn)
users = pd.read_sql('SELECT * FROM users', db_conn)

# 预关联
orders_with_users = orders.merge(users, on='user_id', how='left')

# 只选择需要的列
orders_with_users = orders_with_users[[
    'order_id', 'user_id', 'user_name', 'user_level',
    'order_time', 'amount', 'status'
]]

# 写入 ClickHouse
orders_with_users.to_clickhouse('orders_analysis')
─────────────────────────────────────────────────────────────────
```

### 4. 数据脱敏和加密

```
┌─────────────────────────────────────────────────────────────────┐
│                    ETL: 数据脱敏                                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ETL 阶段:                                                       │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                                                          │   │
│  │  1. 敏感信息脱敏                                         │   │
│  │     - 手机号中间四位打码                                  │   │
│  │     - 身份证号脱敏                                       │   │
│  │     - 邮箱脱敏                                           │   │
│  │                                                          │   │
│  │  2. 数据加密                                             │   │
│  │     - 字段级加密                                         │   │
│  │     - 哈希处理                                           │   │
│  │                                                          │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  为什么?                                                         │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ • ClickHouse 没有内置脱敏功能                           │   │
│  │ • 敏感数据不应进入分析系统                               │   │
│  │ • 合规要求                                                │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

示例:
─────────────────────────────────────────────────────────────────
# 数据脱敏 (ETL)
import hashlib

def mask_phone(phone):
    if pd.isna(phone):
        return None
    return phone[:3] + '****' + phone[7:]

def mask_idcard(idcard):
    if pd.isna(idcard):
        return None
    return idcard[:6] + '********' + idcard[14:]

# 应用脱敏
df['phone'] = df['phone'].apply(mask_phone)
df['idcard'] = df['idcard'].apply(mask_idcard)

# 哈希处理
df['user_id_hash'] = df['user_id'].apply(
    lambda x: hashlib.sha256(str(x).encode()).hexdigest()[:16]
)
─────────────────────────────────────────────────────────────────
```

## 应该在 ClickHouse 中完成的任务

### 1. 聚合计算

```
┌─────────────────────────────────────────────────────────────────┐
│                    ClickHouse: 聚合计算                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ClickHouse 擅长:                                               │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                                                          │   │
│  │  1. 大数据量聚合                                         │   │
│  │     - 亿级数据秒级响应                                    │   │
│  │                                                          │   │
│  │  2. 多维度分析                                           │   │
│  │     - GROUP BY 多列                                      │   │
│  │     - CUBE, ROLLUP                                       │   │
│  │                                                          │   │
│  │  3. 近似计算                                             │   │
│  │     - uniq, quantile, topK                              │   │
│  │                                                          │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

示例:
─────────────────────────────────────────────────────────────────
-- ClickHouse 聚合
SELECT 
    toDate(event_time) AS date,
    user_id,
    count() AS pv,
    uniq(session_id) AS uv,
    sum(amount) AS total_amount,
    quantile(0.95)(amount) AS p95_amount
FROM orders
WHERE event_time >= '2024-01-01'
GROUP BY date, user_id
HAVING pv > 100
ORDER BY pv DESC
LIMIT 100;
─────────────────────────────────────────────────────────────────
```

```
│  ┌─────────────────────────────────────────────────────────┐   │

│  │  2. 趋势分析                                            │   │
│  │     - 窗口函数                                           │   │

│  │                                                          │   │

│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

示例:
─────────────────────────────────────────────────────────────────
-- 时间序列分析
SELECT 
    toDate(event_time) AS date,
    count() AS daily_pv,
    -- 7天移动平均
    avg(count()) OVER (ORDER BY toDate(event_time) ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) AS ma7,
    -- 同比
    count() / lagInFrame(count(), 7) OVER (ORDER BY toDate(event_time)) AS ratio_7d
FROM events
WHERE event_time >= '2024-01-01'
GROUP BY date
ORDER BY date;
─────────────────────────────────────────────────────────────────
```

```
FROM events SAMPLE 0.1;

-- Top 100 商品
SELECT topK(100)(product_id) AS top_products
FROM orders;

-- 分位数估算
SELECT 
    quantile(0.5)(amount) AS p50,
    quantile(0.9)(amount) AS p90,
    quantile(0.99)(amount) AS p99
```

## 最佳实践总结

### ETL 职责清单

| 任务 | 推荐位置 | 原因 |
|------|----------|------|
| 数据清洗 | ETL | 更高效,避免脏数据 |
| 格式转换 | ETL | ClickHouse 能力有限 |
| 数据去重 | ETL | 实时去重影响性能 |
| 维度关联 | ETL | JOIN 更高效 |
| 数据脱敏 | ETL | 合规要求 |
| 数据验证 | ETL | 源头控制 |
| 增量计算 | ETL | 减少实时计算 |

### ClickHouse 职责清单

| 任务 | 推荐位置 | 原因 |
|------|----------|------|
| 聚合统计 | ClickHouse | 性能优势明显 |
| 多维分析 | ClickHouse | 向量化执行 |
| 时间序列 | ClickHouse | 分区裁剪 |
| 近似计算 | ClickHouse | 内置函数 |
| 实时查询 | ClickHouse | 低延迟 |
| 大数据量分析 | ClickHouse | 亿级秒级 |

### 设计原则

```
┌─────────────────────────────────────────────────────────────────┐
│                    ClickHouse 最佳设计原则                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 写入即终态                                                   │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  数据进入 ClickHouse 后不应再修改                        │   │
│  │  如需修改,在 ETL 阶段完成                              │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  2. 预计算优先                                                  │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  复杂计算在 ETL 阶段完成                               │   │
│  │  ClickHouse 只做轻量级聚合                             │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  3. 宽表设计                                                    │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  预先 JOIN 维度表                                      │   │
│  │  避免查询时 JOIN                                      │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  4. 不可变数据                                                  │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  事件日志应该是追加型的                                │   │
│  │  使用新批次而非更新旧数据                              │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```
