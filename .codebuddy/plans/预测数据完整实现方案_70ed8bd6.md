## 产品概述

针对大规模交易预测数据场景，构建高性能ClickHouse存储和查询方案，解决156亿行预测数据的导入、存储和查询性能瓶颈，支持Superset实时多维分析。

## 核心需求

### 业务场景

- **基础数据**：每batch约13M行交易数据，90列维度Key（不可分割）
- **预测数据**：数据科学家已生成的156亿行（13M × 60月 × 20指标）
- **指标结构**：4层父子结构，共20个指标
- **查询模式**：每次查询都涉及所有指标、所有年份月份、加上维度分析

### 性能目标

| 瓶颈 | 当前状态 | 目标要求 |
| --- | --- | --- |
| 导入时间 | >1小时 | <2分钟 |
| 查询时间 | >60秒 | <10秒 |
| 数据规模 | 156亿行/batch | 持续扩展 |


### 核心功能

1. **完整DDL/DML**：基础表、维度表、预测表、指标元数据表
2. **模拟数据生成**：支持完整测试验证
3. **Superset兼容**：保留年月、指标、90维度等所有分析维度
4. **性能优化**：导入和查询优化配置

## 技术栈选择

- **数据存储**：ClickHouse ReplicatedMergeTree 系列引擎
- **数据建模**：维度分离 + 数组存储（Array(Array(Float64))）
- **查询优化**：物化视图、ARRAY JOIN、跳数索引、查询缓存
- **导入优化**：Native格式、并行写入、批量提交

## 核心技术方案

### 1. 存储模型重构 - 维度分离 + 数组存储

**原结构问题**：

```
transaction_key | dim1...dim90 | prediction_month | metric_id | metric_value
     ↓              ↓              ↓
  重复1200次    重复1200次      重复20次
同一transaction_key的90维度重复了1200次（60月 × 20指标）
```

**优化后结构**：

```
1. 维度表 transaction_dimensions（13M行）：
   transaction_key | dim1 | dim2 | ... | dim90

2. 预测表 predictions（13M行）：
   transaction_key | batch_id | metrics_values Array(Array(Float64))
   - metrics_values[metric_id][month_offset] = value
   - 20个指标 × 60个月份 = 1200个值压缩为单个二维数组

3. 指标元数据表 metric_metadata（20行）：
   metric_id | metric_name | level | parent_metric_id | full_path

4. 年月映射表 month_mapping（60行）：
   month_id | year_month | year | quarter | month_offset
```

**数据量对比**：

- 原方案：156亿行/batch
- 优化方案：2600万行/batch（**减少99.8%**）

### 2. 导入优化方案

**策略**：

- 数据量优化：实际导入2600万行（减少99.8%）
- 并行写入：`max_insert_threads = 8`
- Native格式：避免CSV解析开销
- 批量提交：每批 ≥ 100万行

**预估性能**：2600万行使用并行+Native格式，预计30-60秒完成

### 3. 查询优化方案

**策略**：

- 展开视图：ARRAY JOIN按需展开，不物理存储
- 物化聚合视图：预计算常用聚合组合
- 分区裁剪：PARTITION BY batch_id
- 排序键：ORDER BY (batch_id, transaction_key)
- 查询缓存：use_query_cache = 1

### 4. 指标层级聚合支持

4层父子结构，支持层级汇总：

```
Level 1: Total_Revenue
  └── Level 2: Product_Revenue
        ├── Level 3: Online_Revenue
        │     ├── Level 4: Mobile_Revenue
        │     └── Level 4: Web_Revenue
        └── Level 3: Offline_Revenue
              └── Level 4: Store_Revenue
```

## 实现注意事项

### 性能关键点

1. **维度分离是核心**：避免1200倍冗余是关键
2. **批量大小**：插入批次 ≥ 100万行
3. **数组优化**：使用二维数组存储指标和月份
4. **查询缓存**：启用查询缓存减少重复计算

### 数据类型优化

- metric_id: UInt8（最多20个指标）
- month_offset: UInt8（1-70）
- 预测值: Float64
- 避免Nullable，使用默认值

### Superset兼容性

- 创建展开视图供Pivot Table使用
- 维度通过JOIN维度表获取
- 年月、指标通过ARRAY JOIN展开
- 支持指标层级聚合查询
