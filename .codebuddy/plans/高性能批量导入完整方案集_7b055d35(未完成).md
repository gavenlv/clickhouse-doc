## 产品概述

为 ClickHouse 创建双套高性能批量导入方案，针对 150 亿行 Parquet 数据从 GCS 导入的场景，目标将导入时间从 30 分钟大幅优化。

## 核心功能

- **方案A（单分片优化）**：多客户端并行导入、极限参数调优、异步复制，预期5-10分钟
- **方案B（多分片架构）**：改造为4分片×2副本架构、分布式并行写入，预期1-2分钟
- **GCS Parquet 文件直接读取**：使用 S3/GCS 表函数，避免中间存储
- **分片并行导入脚本**：多客户端同时导入不同文件
- **导入性能监控**：实时监控和性能基准测试
- **错误恢复机制**：断点续传和幂等性保证
- **CPU 和内存资源优化**：避免过载，平衡吞吐量和稳定性

## 架构瓶颈分析

当前架构为**单分片双副本**，存在以下核心瓶颈：

| 瓶颈类型 | 性能损失 | 占比 | 解决方案 |
| --- | --- | --- | --- |
| 单分片架构限制 | 15x | 50% | 方案B：扩展为多分片 |
| 双副本同步开销 | 2x | 15% | 异步复制优化 |
| 单节点资源限制 | 3x | 20% | 多线程并行优化 |
| 导入参数未优化 | 2x | 15% | 参数调优 |


**总性能差距**：30倍（当前30分钟 vs 目标1分钟）

## Tech Stack

- ClickHouse 集群（当前：1分片×2副本；方案B：4分片×2副本）
- GCS 存储集成（S3/GCS 表函数）
- Parquet 格式数据导入
- SQL 脚本 + Shell 脚本
- ClickHouse Keeper（3节点，Raft协调）

## Implementation Approach

### 方案A：单分片极致优化（短期快速方案）

**核心策略**：

1. **多客户端并行导入**：启动8-16个客户端，每个导入不同的Parquet文件
2. **最大化插入线程**：`max_insert_threads = 48`（充分利用95核CPU）
3. **异步复制**：`insert_quorum = 1`，允许副本异步复制，降低延迟
4. **批量参数优化**：`max_insert_block_size = 1048576`，减少小批量写入
5. **GCS直接读取**：使用`gcs()`函数直接读取，避免中间存储

**性能预期**：

- 提升幅度：8-12倍
- 最终性能：5-10分钟导入
- 实施难度：低（无需架构变更）

### 方案B：多分片架构改造（长期推荐方案）

**核心策略**：

1. **架构扩展**：从1分片×2副本 → 4分片×2副本 = 8节点
2. **数据分片**：按业务键（如user_id、日期）分片，实现分布式并行
3. **分布式写入**：通过Distributed表自动路由到各分片
4. **负载均衡**：写入压力分散到4个分片，每分片处理37.5亿行

**性能预期**：

- 提升幅度：15-20倍
- 最终性能：1-2分钟导入
- 实施难度：中（需扩展节点和迁移数据）

### 混合实施策略

1. **阶段1（本周）**：实施方案A，快速达到5-10分钟
2. **阶段2（下周）**：评估是否需要达到1分钟目标
3. **阶段3（可选）**：实施方案B，扩展为多分片架构

## Key Code Structures

### 方案A核心导入配置

```sql
-- 方案A：单分片极致优化配置
SETTINGS 
    max_insert_threads = 48,                    -- 并行插入线程（95核CPU）
    max_insert_block_size = 1048576,            -- 1M行块
    min_insert_block_size_rows = 1000000,       -- 最小批量
    input_format_parallel_parsing = 1,          -- 并行解析Parquet
    input_format_parquet_max_block_size = 1000000,
    insert_quorum = 1,                          -- 异步复制（只等1副本）
    insert_quorum_timeout = 300000;
```

### 方案B核心架构配置

```sql
-- 方案B：多分片集群配置
<remote_servers>
    <treasurycluster_4shards>
        <shard>
            <internal_replication>true</internal_replication>
            <replica><host>clickhouse1</host><port>9000</port></replica>
            <replica><host>clickhouse2</host><port>9000</port></replica>
        </shard>
        <shard>
            <internal_replication>true</internal_replication>
            <replica><host>clickhouse3</host><port>9000</port></replica>
            <replica><host>clickhouse4</host><port>9000</port></replica>
        </shard>
        <!-- Shard 3, 4 类似 -->
    </treasurycluster_4shards>
</remote_servers>

-- 分布式表写入
SETTINGS 
    max_insert_threads = 16,              -- 每节点16线程
    prefer_localhost_replica = 0,         -- 分布式写入所有分片
    insert_quorum = 2,                    -- 等待2副本确认
    insert_distributed_sync = 2;          -- 同步写入所有分片
```

### GCS 直接导入示例

```sql
-- 从GCS直接导入Parquet到ClickHouse
INSERT INTO target_table
SETTINGS 
    max_insert_threads = 48,
    max_insert_block_size = 1048576
SELECT * FROM gcs(
    'https://storage.googleapis.com/bucket/path/*.parquet',
    'your-access-key',
    'your-secret-key',
    'Parquet',
    -- schema auto-detection or explicit definition
    'col1 String, col2 UInt64, col3 DateTime, ...'
);
```
