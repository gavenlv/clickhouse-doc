### 核心原则

```
┌─────────────────────────────────────────────────────────────────┐
│                    ClickHouse 核心原则                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 写入优化                                                    │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  ✗ 频繁小批量写入 → 大量小 Parts,合并压力大           │   │
│  │  ✓ 批量写入 (每批 > 10万行) → 减少 Parts 数量        │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  2. 查询优化                                                    │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  ✗ SELECT * → 只选需要的列                             │   │
│  │  ✗ 缺少 WHERE 条件 → 使用分区裁剪                     │   │
│  │  ✓ 物化视图预聚合 → 减少实时计算                      │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  3. 表设计                                                      │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  ✗ 主键顺序不当 → 索引效率低                          │   │
│  │  ✓ 高选择性列放前面 → 快速过滤                        │   │
│  │  ✗ 分区过细 → 大量小 Parts                           │   │
│  │  ✓ 分区合理 → 控制 Parts 数量                        │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  4. 数据类型                                                    │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  ✗ String 存储日期/数值 → 占用大,计算慢              │   │
│  │  ✓ 使用合适的数据类型 → Date, Int32 等              │   │
│  │  ✓ 使用 LowCardinality → 减少内存占用                │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 📊 最佳实践清单

### 表设计

```sql
-- ✓ 正确的主键顺序
CREATE TABLE t1 (
    event_date Date,
    user_id UInt32,
    event_type String,
    id UInt64
) ENGINE = MergeTree()
ORDER BY (event_date, user_id, id);  -- 高选择性在前

-- ✗ 错误的主键顺序
CREATE TABLE t2 (
    event_date Date,
    user_id UInt32,
    event_type String,
    id UInt64
) ENGINE = MergeTree()
ORDER BY (event_type, event_date, user_id);  -- 低选择性在前
```

### 写入优化

```sql
-- ✓ 批量写入
INSERT INTO table SELECT * FROM large_dataset;

-- ✗ 频繁小写入
for row in data:
    INSERT INTO table VALUES (row)  -- 每次一行
```

### 查询优化

```sql
-- ✓ 只选需要的列
SELECT user_id, count() FROM table GROUP BY user_id;

-- ✗ SELECT *
SELECT * FROM table;  -- 读取所有列

-- ✓ 使用分区裁剪
SELECT * FROM table WHERE event_date = '2024-01-01';

-- ✗ 全表扫描
SELECT * FROM table;
```

## 🔍 常见问题速查

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 写入慢 | 小批量频繁写入 | 批量写入 > 10万行 |
| 查询慢 | SELECT * | 只选需要的列 |
| 内存高 | 主键不当 | 优化主键顺序 |
| 磁盘大 | 数据类型不当 | 使用合适的数据类型 |
| 合并慢 | Part 过多 | 批量写入 + 合理分区 |
| CPU 高 | 向量化未启用 | 检查 settings |
